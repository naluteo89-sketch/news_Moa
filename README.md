# news_Moa · 뉴스 분석

네이버 뉴스 검색 결과를 모아, 기사마다 **긍정·부정 분위기**와 **핵심 키워드·핵심 문장**을 바로 보여주는 웹 서비스입니다.
검색량·언급량 숫자 위주인 기존 분석 서비스와 달리, **기사를 직접 읽으며 "무슨 이야기가 오가는지"를 빠르게 파악**하는 데 초점을 맞췄습니다.

## 이 프로젝트의 특별한 점

### 1. 숫자가 아니라 "근거"를 보여주는 감성 분석
긍정 65.9%라는 숫자만 내놓지 않고, 그렇게 판단한 **감성 단어(근거)** 를 함께 보여줍니다. 사용자는 기사를 열어 그 판단이 맞는지 바로 확인할 수 있습니다.
목록 단계에서도 기사마다 긍정·부정·중립 표식과 카드 끝 색 띠가 붙어, 스크롤만 해도 페이지 분위기가 읽힙니다.

### 2. 제목과 겹치는 "핵심 문장"으로 바로 이동
기사 제목·부제목의 명사를 가장 많이 담은 문장을 순위로 보여주고, 누르면 **본문 박스 안의 그 문장으로 스크롤해 노랗게 강조**합니다. 긴 기사도 핵심 문단부터 읽을 수 있습니다.

### 3. 막힌 원본 대신 "본문을 직접 펼치는" 읽기 방식
처음에는 원본 기사를 팝업(iframe)으로 띄우려 했지만, 점검 스크립트로 확인해 보니 언론사 상당수가 iframe을 막고 있었습니다(20건 중 7건). 그래서 서버가 **본문·부제목·사진을 직접 추출해 카드 아래로 펼치는 방식**으로 설계를 바꿨습니다. 네이버 뉴스 본문 추출은 7/7 성공, 실패할 때는 검색 요약으로 분석하고 화면에 그 사실을 알립니다.

### 4. 단어·언론사를 겹쳐 거는 "걸러보기"
왼쪽의 많이 나온 단어와 언론사를 함께 걸면 "‘AI’ 포함 · 연합뉴스 기사 2건"처럼 조건에 맞는 기사만 남기고 단어를 강조합니다. 비는 날짜 구분선은 함께 숨고, 0건이면 해제 버튼을 안내합니다.

### 5. 처음 쓰는 사람과 자세히 보는 사람을 모두 고려한 화면
- **사용법 5단계 안내**: 실제 화면 캡처와 설명을 나란히 보여주고, 닫으면 다시 뜨지 않습니다.
- **전문가 모드**: 평소에는 화면을 단순하게 두고, 스위치를 켜면 페이지 전체 키워드 분포·기사 시간 분포가 추가됩니다.
- **다크 모드**: 컴퓨터 테마를 따라가고 버튼으로 바꿀 수 있습니다. 어두운 배경에서 사진·글 상자가 묻히지 않도록 흰 테두리를 둘렀습니다.

### 6. 화면 크기와 무관하게 깨지지 않는 레이아웃
- 좌우 패널이 화면보다 길면 페이지와 함께 내려가다 **아래쪽이 화면 끝에 닿는 위치에서 고정**되어, 안쪽 스크롤 없이 끝까지 볼 수 있습니다.
- 사진은 실제 크기를 먼저 확인해 **아이콘·로고는 빼고**, 세로로 긴 사진이 카드를 늘리거나 작은 사진이 확대돼 흐려지지 않게 처리했습니다.
- 본문 박스 크기, 고정 검색어, 최근 검색어, 테마, 전문가 모드는 브라우저에 기억됩니다.

## 주요 기능

### 검색
- 네이버 뉴스 검색 API로 기사 검색 (10/20/50/100건, 정확도순/최신순). 건수·정렬을 바꾸면 바로 다시 검색
- 처음 화면은 기본 검색어(`축제`)로 시작
- 위아래 페이지 이동 (API 한도에 맞춰 최대 1,000건)
- **고정 검색어(핀)**: 자주 보는 검색어를 상단에 고정하고 × 로 해제, `+` 로 지금 검색어 추가
- 최근 검색어 기록 (최대 8개)

### 기사 목록
- 기사 페이지에서 가져온 **썸네일**, 원문 주소로 찾은 **언론사 이름**(약 70곳, 없으면 기사 페이지의 `og:site_name`)
- 기사마다 **긍정(파랑)·부정(빨강)·중립(회색) 표식**과 카드 오른쪽 끝 색 띠
- 날짜가 바뀌는 곳마다 **"오늘 · 10월 26일 (월) 뉴스"** 같은 구분선
- 왼쪽 **많이 나온 단어**·**언론사별 기사**를 누르면 해당 기사만 보기 (함께 걸 수 있음)

### 기사 펼쳐 읽기
- 기사를 누르면 아래로 **본문·부제목·사진**이 펼쳐짐 (원본 iframe은 대부분 언론사가 막아 직접 본문을 추출)
- 본문 박스는 안에서 스크롤, 아래 모서리로 크기 조절 → 조절한 크기를 기억
- 왼쪽 **핵심 문장**: 제목·부제목과 겹치는 단어가 많은 문장 순위. 누르면 본문의 그 위치로 이동해 강조
- 오른쪽 **기사 분석**: 긍정·부정 도넛 차트, 근거가 된 감성 단어, 자주 쓰인 단어, 단어 구름

### 페이지 전체 보기
- 오른쪽 위 **이 페이지 기사 분위기**: 긍정·부정·중립 뉴스 수와 비율. 목록에서 기사를 누르면 그 기사로 이동해 펼침
- **전문가 모드** 스위치: 켜면 "한눈에 보는 키워드"(페이지 전체 단어 크기 분포), "기사 시간 분포"(날짜·시간대별 기사 수)가 추가로 보임

### 화면
- **다크 모드**: 컴퓨터 테마를 따라가고, 상단 버튼으로 시스템 → 다크 → 라이트 전환. 다크 모드에서는 카드·사진에 흰 테두리
- 사용법 5단계 안내 칸 (닫으면 기억, `? 사용법`으로 다시 열기)
- 좌우 패널이 화면보다 길면 페이지와 함께 내려가다 아래쪽에서 멈추는 고정 방식(안쪽 스크롤 없음)
- 사진 크기 확인: 아이콘·로고처럼 작은 그림은 빼고, 세로로 긴 사진도 카드 높이를 바꾸지 않음

## 분석 방식

| 항목 | 방법 |
|---|---|
| 긍정·부정 | [KNU 한국어 감성사전](https://github.com/park1200656/KnuSentiLex)의 단어 극성(-2~2)을 합산. `좋지 않다`, `안 좋다` 같은 부정 표현은 극성을 뒤집음. 한쪽이 60% 이상이면 긍정/부정, 아니면 중립 |
| 형태소 분석 | `kiwipiepy` 사용. 설치되지 않은 환경에서는 조사를 떼어내는 간이 분석기로 자동 대체 |
| 핵심 키워드 | 명사 빈도(기사 하나), 페이지 전체는 "몇 개 기사에 나왔는지" 순. 검색어 자체는 제외 |
| 핵심 문장 | 문장의 명사가 제목 명사를 얼마나 포함하는지(60%) + 부제목 명사를 얼마나 포함하는지(40%) |
| 본문 수집 | 네이버 뉴스 페이지는 본문 영역(`#dic_area`)을, 언론사 원문은 `trafilatura` 또는 간이 추출. 실패하면 검색 요약으로 분석하고 화면에 안내 |

> AI(OpenAI) 분석은 다음 단계로 계획 중이며, 지금 버전은 파이썬 규칙 기반 분석만 포함합니다.

## 구조

```txt
news_Moa/
  main.py                 Flask 웹 서버 (화면 + API)
  components/
    naver_news_search.py  네이버 뉴스 검색 API 호출, 결과 정리
    article_fetcher.py    기사 본문·부제목·사진·언론사 이름 수집 (캐시)
    text_analyzer.py      감성 분석, 키워드, 핵심 문장, 페이지 키워드
    press.py              원문 주소 → 언론사 이름
  templates/index.html    화면 (HTML·CSS·JS 한 파일)
  static/tutorial/        사용법 안내 이미지
  check_article_fetch.py  API 결과 링크로 본문·사진을 가져올 수 있는지 점검하는 스크립트
  docs/                   README 스크린샷
```

| 주소 | 내용 |
|---|---|
| `GET /` | 검색 화면 (`query`, `display`, `start`, `sort`) |
| `GET /api/news` | 검색 결과 JSON |
| `GET /api/preview` | 목록용: 썸네일 후보, 언론사 이름, 긍정·부정 판정 |
| `GET /api/article` | 기사 본문 + 분석 결과 (문단·문장, 감성, 키워드, 핵심 문장) |

## 실행 방법

```bash
pip install -r requirements.txt
python main.py        # http://127.0.0.1:5000
```

- **API 키**: 저장소에 넣지 않고 `C:\keydata\naver.py`에 둡니다. 다른 위치면 환경변수 `NAVER_KEY_FILE`로 지정합니다.
  ```python
  CLIENT_ID = "네이버 개발자센터 Client ID"
  CLIENT_SECRET = "Client Secret"
  ```
- **감성사전**: 처음 실행할 때 `data/SentiWord_info.json`으로 자동 다운로드됩니다. (연구용 공개 자료, `.gitignore`로 저장소 제외)
- `kiwipiepy`가 설치되지 않는 Python 버전에서는 간이 분석기로 동작합니다. 기사 분석 칸 오른쪽 아래 "형태소 분석: simple/kiwipiepy"로 확인할 수 있습니다.

## 점검 결과

`check_article_fetch.py`로 실제 API 결과 20건을 점검한 결과입니다.

| 항목 | 결과 |
|---|---|
| 네이버 뉴스 링크 비율 | 7/20 (35%) |
| 네이버 뉴스 본문 추출 | 7/7 성공 |
| 언론사 원문 본문 추출 | 15/20 성공 |
| iframe(원본 화면 끼워 넣기) 차단 | 7/20 → 본문을 직접 추출해 펼치는 방식 선택 |

## 개발 중 해결한 문제

| 문제 | 원인 | 조치 |
|---|---|---|
| 오버레이에 원본 기사를 띄우려 했으나 빈 화면 | 언론사·네이버가 iframe을 막음 | 서버가 본문을 추출해 카드 아래로 펼침 |
| 세로로 긴 사진이 카드를 446px까지 늘림, 작은 사진은 확대돼 흐림 | 썸네일 높이가 사진 비율을 따라감, 갤러리가 무조건 꽉 채움 | 썸네일은 칸을 채우고 자름, 본문 사진은 원래 크기 이하로만 표시, 100×60 미만 그림 제외 |
| 제목에 `&quot;`, `<b>` 가 그대로 보임 | API 응답이 HTML 엔티티·태그 포함 | 태그 제거 + `html.unescape` |
| 일부 언론사 본문이 깨짐 | EUC-KR 페이지가 인코딩을 명시하지 않음 | 응답 인코딩을 내용 기반으로 추정 |
| 좌우 패널 안에 스크롤바가 생김 | 고정 패널에 최대 높이를 둠 | 높이 제한을 없애고, 화면보다 길면 아래쪽에 맞춰 고정 |
| 화면 110% 확대 후 패널 위치가 어긋남 | 확대 배율이 화면 높이 계산에 반영되지 않음 | 배율을 읽어 계산 보정 |
| 걸러보기 결과가 0건이면 가운데가 텅 빔 | 안내 문구 없음 | "조건에 맞는 기사가 없어요" + 해제 버튼 |
| API 키가 코드에 들어 있음 | 초기 예제 코드 | 저장소 밖 키 파일에서 읽도록 변경 |
